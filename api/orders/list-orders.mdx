---
title: "List orders"
description: "Retrieve a paginated list of orders for the authenticated user."
api: "GET /orders"
---

Returns the user's orders, sorted by creation date descending.

## Query parameters

<ParamField query="limit" type="integer" default="50">
  Number of results to return. Min `1`, max `100`.
</ParamField>

<ParamField query="offset" type="integer" default="0">
  Number of results to skip for pagination.
</ParamField>

<ParamField query="status" type="string">
  Filter by order status. One of: `new`, `waiting_payment`, `paid`, `provisioning_failed`, `provisioned`, `cancelled`, `refunded`, `expired`. See [Order statuses](/api/orders/create-order#order-statuses).
</ParamField>

## Response

<ResponseField name="orders" type="array">
  List of order objects. Same shape as [Create order response](/api/orders/create-order#response).
  <Expandable title="Payment link">
    <ResponseField name="payment_url" type="string">
      Where to send the customer to pay. Set while `status` is `waiting_payment` for any external payment method (card checkout, crypto, SBP, Telegram Stars), `null` otherwise.
    </ResponseField>
  </Expandable>
  <Expandable title="Tariff length">
    <ResponseField name="period_days" type="integer">
      Rental period in days. Never below `1`, so a mobile rotating tariff shorter than a day also reads `1` here.
    </ResponseField>
    <ResponseField name="period_seconds" type="integer | null">
      Length of the purchased tariff in seconds. Use it for tariffs shorter than a day: a 1-hour order has `period_days: 1` and `period_seconds: 3600`. `null` when the order was placed without a fixed tariff.
    </ResponseField>
  </Expandable>
  <Expandable title="Mobile rotating traffic">
    <ResponseField name="traffic_total_mb" type="integer | null">
      Traffic included in the current plan, in megabytes. `null` when the plan has no cap or the value was not reported.
    </ResponseField>
    <ResponseField name="traffic_remaining_mb" type="integer | null">
      Traffic left on the current plan, in megabytes; `0` means the allowance is spent. `null` when the plan has no cap or the value was not reported.
    </ResponseField>
    <ResponseField name="traffic_unlimited" type="boolean">
      `true` when the plan has no traffic cap. Tells "no cap" apart from "not reported", which both leave the two figures `null`.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="total" type="integer">
  Total number of orders matching the filter.
</ResponseField>

<Note>
  The traffic figures in this list are the ones stored at the last update of the proxy, so they can lag behind actual usage. [Get order](/api/orders/get-order) reads the same three fields live for a mobile rotating order.
</Note>

<Note>
  To find orders that still wait for payment, filter with `status=waiting_payment`: each one carries the `payment_url` to send the customer to. When the payment window closes unpaid, the order becomes `expired` and `payment_url` is `null`. A payment that arrives after that may be credited to your account balance, depending on the payment method; the order stays `expired`. See [Payment methods](/overview/payment-methods#unpaid-orders-and-the-payment-window) for what happens to a payment that arrives late.
</Note>

## Example

<CodeGroup>

```bash cURL
curl "https://api.proxyjam.com/public/v1/orders?limit=10" \
  -H "X-API-Key: pj_AbCdEf..."
```

```python Python
from proxyjam import ProxyJamClient

with ProxyJamClient(api_key="pj_live_...") as proxyjam:
    page = proxyjam.orders.list(limit=10, offset=0)
    for order in page.orders:
        print(order.id, order.status, order.country)
    print(f"total: {page.total}")
```
